# 产品需求

## 产品定位

品牌舆情监控系统是一套本地桌面应用。用户在应用内维护品牌、关键词和平台账号，
系统按计划自动巡检抖音、小红书公开内容，识别需要关注的舆情，形成可查询、可复核、
可播报的本地台账。

## 核心流程

1. 用户创建品牌，并为品牌维护一个或多个检索关键词、别名或主体公司名称。
2. 用户在应用内为抖音、小红书添加账号，并在自动巡检浏览器中手动登录。
3. 每个“平台 + 账号”使用独立持久化 Playwright 浏览器档案，不导出 Cookie、不保存密码。
4. 应用常驻运行，按用户配置的周期依次检索所有启用关键词。
5. 系统保存原帖、作者、时间、正文、评论、互动数据和发现时间，并进行去重。
6. 规则先做低成本初筛；配置大模型后进行相关性、类型、风险和摘要复判。
7. 需要关注的内容进入舆情中心；疑似/高风险相似内容聚合为同一舆情事件。
8. 应用内提供即时提醒、未读通知以及包含聚合统计的每日简报。

## 功能范围

### 第一阶段

- 品牌与多关键词增删改、启停。
- 抖音、小红书多账号管理及独立登录态。
- 桌面应用提供与自动巡检一致的账号登录入口和登录态检查。
- 后台定时巡检和手动立即巡检。
- 本地 SQLite 舆情台账、P0-P3 分级和人工复核。
- 应用内概览、舆情列表、运行状态和通知中心。
- 无大模型 API Key 时仍可使用规则完成基本判断。
- 企微智能机器人日报：当天首次完成的定时巡检或 Agent 导入发送一条 Markdown 日报；手动巡检每次成功或部分完成都发送一条。
- 可选大模型辅助复判：规则先筛选，再对高风险或待复核内容调用兼容 OpenAI 接口；
  API Key 使用 Windows 凭据管理器保存。

### 已完成的后续能力

- 文本大模型辅助相关性、类型、风险和摘要复判；图片/视频不发送给模型。
- 同平台、同品牌、同标准化标题的事件聚类和日报聚合统计；语义相似聚类仍需后续验证。
- 桌面源码运行时的系统托盘恢复和退出入口，以及可选的当前用户开机启动。

### 暂不包含

- 带签名、升级和卸载能力的桌面安装器；当前仅提供压缩包。
- 更丰富的企微通知渠道和日报模板配置。

### 明确不做

- 自动填写或提交平台举报。
- 自动申诉下架或绕过平台验证。
- 导出 Cookie、记录账号密码或绕过访问频率限制。

## 舆情记录

每条记录至少包含品牌、命中关键词、平台、原帖链接、作者、发布时间、正文或摘要、
评论快照、首次发现时间、最近发现时间、舆情类型、风险等级、判断依据、人工复核状态
和处理备注。

## 验收原则

- 三个初始品牌及其同名关键词可直接使用，后续可在应用中维护。
- 不同平台账号的浏览器数据目录互相隔离，同一档案不能并发打开。
- 没有 API Key 不影响关键词巡检、规则分类、台账和应用内通知。
- 所有高风险自动判断都以“疑似”呈现，人工结论不被后续自动规则覆盖。
- 登录失效、验证码和限流必须可见并等待人工处理，不能静默绕过。
