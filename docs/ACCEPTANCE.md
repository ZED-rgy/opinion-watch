# 桌面基础版验收

本轮验收目标是确认桌面应用骨架、品牌关键词、多账号独立登录档案、舆情中心、应用内
播报和定时巡检入口可用。自动巡检与账号登录必须复用同一套账号档案。

## 1. 安装与基础检查

```powershell
uv sync --dev --extra desktop
uv run opinion-watch init
uv run ruff check .
uv run ruff format --check .
uv run pytest
uv run opinion-watch-desktop --smoke-test
```

通过标准：Ruff 通过，pytest 全部通过，桌面冒烟返回 `status: ok` 和 `pages: 6`。

## 2. 启动桌面应用

```powershell
uv run opinion-watch-desktop
```

通过标准：应用默认打开“自动巡检”，左侧可切换自动巡检、品牌与关键词、平台账号、
舆情中心、应用内播报和设置；首页品牌、关键词和账号状态与各管理页一致。业务数据为空
时，巡检动态、舆情中心和应用内播报均显示空状态，不显示演示数据。

## 3. 品牌关键词

1. 确认速探长、优速卖、配达人存在且各有一个同名启用关键词。
2. 为任一品牌新增一个测试关键词。
3. 重命名、停用、重新启用该关键词。
4. 删除测试关键词。

通过标准：所有操作立即反映到表格；品牌和关键词状态彼此独立。

## 4. 平台账号与独立登录态

1. 分别新增一个抖音账号和一个小红书账号，可使用相同备注名。
2. 选择账号并打开自动巡检浏览器，手动登录后点击“登录完成并检查”。
3. 关闭对应登录窗口，再次从同一账号打开。
4. 确认仍保持登录；另一个账号不共享该登录态。

通过标准：同平台不同账号可以同时存在；每个账号对应独立稳定目录；重新打开同一账号
能够复用同一个账号的 Playwright 登录态。若平台要求验证码，应人工完成，不绕过。

## 5. 舆情中心与应用内播报

1. 完成一次真实巡检后，打开“舆情中心”，查看分类、风险等级、判断依据和原帖入口。
2. 选择一条待复核内容，填写人工分类、等级、审核人和备注。
3. 打开“应用内播报”，检查该记录对应通知变为已读。
4. 选择其他通知并手动标记已读。

通过标准：人工结论保存为 `manual/reviewed`，后续规则重算不会覆盖；未读数量同步更新。

## 6. 手动巡检与定时器

1. 在“自动巡检”点击“立即巡检”，观察运行状态。
2. 任务结束后确认“巡检动态”出现一条带中文状态、时间和采集量的记录；需要诊断时再
   展开运行详情。
3. 到舆情中心和应用内播报查看本次巡检结果。
4. 启用定时巡检并设置周期，保持应用最小化运行。

通过标准：界面不被冻结；任务不会并发重复启动；完成后产生运行记录、分类和对应播报。
巡检开始前会逐个平台检查账号登录态；某个平台失效时，该平台会被跳过并生成明确告警。

## 7. 大模型辅助复判（可选）

1. 在“设置”的“大模型辅助研判”中填写兼容 OpenAI `chat/completions` 的 Base URL、
   模型名和 API Key，点击“保存大模型配置”。
2. 点击“测试连接”，确认接口返回成功。
3. 开启一次巡检，检查高风险或待复核内容的判定来源变为 `model`，并保留人工复核入口。
4. 关闭大模型后再次巡检，确认规则分类仍可正常完成。

通过标准：未配置 API Key 时规则巡检不受影响；模型请求失败只生成告警并保留规则结论；
`manual` 结论不会被模型或规则覆盖。

## 本轮不验收

- 带签名、升级和卸载能力的正式安装器；当前验收源码运行、CI 压缩包及其二进制冒烟、
  桌面系统托盘菜单和设置页开机启动开关。
- 自动举报、申诉和下架结果跟踪。
